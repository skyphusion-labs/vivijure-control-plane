A named credential records operator:<name>. The shared root credential records admin-token and names nobody, which is what it is for. Reading a single tenant's data writes an audit row, including fetching a rendered smoke-render artifact. How this works, exactly

This credential

    A scope bounds what this credential can DO. It is only loosely a bound on what its holder can SEE: reading a tenant reaches their rendered smoke-render output. Ask for the narrowest set that does the job.

    Break-glass credential

    This console will not drive routine work with the shared root credential.

    The privacy policy says routine support access is made with a named credential tied to one operator, and that the shared credential is for emergencies and for managing credentials. Its actions record admin-token and name no person, so using it for ordinary support would make the trail un-attributable and that sentence untrue. Mint yourself a named credential below and sign in with it.

    The API itself still accepts this credential, deliberately: disarming break-glass in the gate would remove it at the moment it exists for. This restriction is the console declining, not the platform refusing.
