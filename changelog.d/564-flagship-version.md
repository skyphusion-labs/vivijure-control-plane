### ci(drift): compare the flagship Worker's deployed version with the newest tag and the latest release (#564)

The daily `studio-pin-drift` workflow gains a step, `npm run check:flagship-version` (`scripts/check-flagship-version.mjs`). It reads the version out of the deployed `vivijure-studio` bytes (the `PACKAGE_VERSION` constant cf bakes from `package.json`) and compares it with vivijure-cf's newest `v*.*.*` tag, ordered by semver, and its latest published release. It fails when the flagship is ahead of the latest published release (a release deployed and did not publish, the cf#1023 shape that held from 2026-10-14 to 2026-10-19), ahead of the newest tag, or behind it. It cannot measure, and says so, when the marker is missing or appears with two values, a read fails, or no tag can be read. The existing pin check compared the pin with "latest published", so it froze with the pin and could not see this pair.
