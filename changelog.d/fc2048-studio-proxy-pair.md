### fix(provision): a proxied tenant studio holds the RunPod proxy pair, not the key (fleet-chezmoi#2048)

`installInvokeKey` no longer installs `RUNPOD_API_KEY` on a proxied (shared-tier) tenant studio. It installs `RUNPOD_PROXY_BASE` and `RUNPOD_PROXY_TOKEN` on the studio (as secrets, so a studio upgrade keeps them), deletes any `RUNPOD_API_KEY` left from an earlier install, and reads the studio secret names back, refusing the install if the pair is missing or the key is still present. The proxy decision is the same `tenantModuleProxyBinding` expression the modules use, so the studio and its modules cannot disagree. Unproxied tenants (dedicated, BYO, self-host) are unchanged. New `CfApi.deleteScriptSecret`, where a 404 counts as success. Requires the studio release to read the pair (vivijure-cf v1.21.0 or later, on vivijure-core 1.10.0 or later). Re-running the invoke-key install on an existing shared tenant moves it onto the pair.
